# crc.aws

## Purpose

AWS cleaners (boto3). They delete or stop leftover EC2, EBS, network, key and KMS resources across regions.

`keypairs/`, `elastic_ips/`, `kms/`, `snapshot/`, `vm/`, `disk/` and `spot_instance_requests/` are `Cleaner`s registered under `aws`; `crc/cli` runs them through `crc.core.engine` (routes in `crc/cli/routes/aws.py`). `_base.py`, `_common.py`, `_regionlog.py` and `connectivity.py` are shared plumbing and register nothing. `vm/` serves `--scan_tag` through `scan_tag()`. Any change must follow `ARCHITECTURE.md`, with `make check` green.

Modules:

- `_base.py`: `get_all_regions` (region list via `describe_regions`, static botocore list on connectivity errors)
- `_regionlog.py`: `start`, `region_done` and `region_skipped`, thin wrappers over `crc.core.logger.current()` with an injectable clock for the `REGION` line (log text only)
- `connectivity.py`: `CONNECTIVITY_ERRORS` and `log_skipped_region` (unreachable regions are logged and skipped)
- `_common.py`: helpers shared by the cleaners below
- `disk/`: `DiskCleaner` (registered as `aws` / `disk`): deletes available EBS volumes (`delete_volume`); tags, regex, `yb_task` and Kubernetes skips, CloudWatch detach age; opt-in `--cloud aws --resource disk`. See `crc/aws/disk/README.md`
- `elastic_ips/`: package (`__init__.py` keeps the import path `crc.aws.elastic_ips`; `crc/aws/elastic_ips/cleaner.py`, `crc/aws/elastic_ips/client.py`): `ElasticIpCleaner` (registered as `aws` / `ip`): releases unassociated, tagged Elastic IPs (`release_address`)
- `keypairs/`: `KeyPairCleaner` (registered as `aws` / `keypair`): deletes key pairs by name regex (`delete_key_pair`). See `crc/aws/keypairs/README.md`
- `kms/`: package (`__init__.py` keeps the import path `crc.aws.kms`; `crc/aws/kms/cleaner.py`, `crc/aws/kms/client.py`, `crc/aws/kms/settings.py`, `crc/aws/kms/tags.py`): `KmsCleaner` (registered as `aws` / `kms`): schedules key deletion (`schedule_key_deletion`) for keys matching description and user ARN
- `snapshot/`: `SnapshotCleaner` (registered as `aws` / `snapshot`): deletes snapshots older than `age_days` (`delete_snapshot`) that carry no exception tag and back no AMI. See `crc/aws/snapshot/README.md`
- `spot_instance_requests/`: `SpotRequestCleaner` (registered as `aws` / `spot_instance_requests`): cancels spot requests, terminates instances, deletes leftover volumes. See `crc/aws/spot_instance_requests/README.md`
- `vm/`: `VmCleaner` (registered as `aws` / `vm`; terminates (`terminate_instances`) or stops (`stop_instances`) running instances), the tag scan behind `--scan_tag` and the typed EC2 Protocols. See `crc/aws/vm/README.md`

## Public API

The modules directly in this package (_base.py, _common.py, _regionlog.py and connectivity.py) are synced with this README by ARCH-002; the keypairs, elastic_ips, kms, snapshot, disk, spot_instance_requests and vm subpackages list their names in their own READMEs.
__init__.py holds only a copyright comment and declares no __all__ (no export list).

- `get_all_regions()`: (_base.py) regions of an AWS service from describe_regions on a client in the default region; a connectivity error falls back to the static botocore region list (Session get_available_regions), every other error propagates.
- CONNECTIVITY_ERRORS (connectivity.py, a constant tuple, not a symbol): the botocore network errors (ConnectionError and its subclasses, ReadTimeoutError, ConnectionClosedError) that skip a region instead of failing; auth errors are not in it.
- `log_skipped_region()`: (connectivity.py) logs the WARNING of a region skipped for a connectivity error (region, context, error type and text).
- `ec2_regions()`, `skip_region()`, `group_by_region()`, `log_deleted_summary()`: (_common.py) shared by the key pair, Elastic IP, KMS, snapshot and disk cleaners: the EC2 region lister (get_all_regions for ec2 in us-west-2), the skipped-region count plus WARNING of a connectivity error, candidates grouped by region, and the "number of ... deleted" / "will be deleted" summary lines. The constants EC2_SERVICE_NAME and DEFAULT_REGION are not symbols. No behaviour of their own.
- `start()`, `region_done()`, `region_skipped()`: (_regionlog.py) timestamp for a region, the REGION run-log line (resources listed, selected, seconds) and the skipped-region count of the core run log; they never decide what is selected or deleted.

## Safety Invariants

- Authoritative text: `CLEANUP_SAFETY.md`. Applicable IDs: SAF-006 to SAF-013 (age gates, shared by all clouds), SAF-001, SAF-003, SAF-004, SAF-014, SAF-015, SAF-016, SAF-017 to SAF-020, SAF-025, SAF-026 to SAF-037.
- Known bugs and quirks: `docs/refactor/BUGS.md` rows `BUG-004`, `BUG-007`, `BUG-008`, `BUG-011`, `BUG-012`, `BUG-014`, `BUG-015`, `BUG-020`, `BUG-021`, `BUG-022`, `BUG-045` to `BUG-061`, and for snapshots `BUG-009`, `BUG-040` and `BUG-142` to `BUG-157`.
- The AWS EBS cleanup needs `--cloud aws --resource disk` (SAF-014); spot requests cancel before terminate (SAF-028).
- Every cleaner runs through `crc.core.engine`: `plan()` lists every region and only reads, then `apply()` mutates, so a listing error in a later region leaves nothing deleted. In a dry run `apply()` is not called.
- Key pairs: `plan()` only calls `describe_key_pairs`; `delete_key_pair` is called from `apply_region()` only and never in a dry run (SAF-006: an empty age matches every key pair, an empty `name_regex` matches every name). Connectivity errors skip the region; every other error propagates (CLEANUP_SAFETY.md). Quirks in `docs/refactor/BUGS.md`: `BUG-045` to `BUG-050`.
- Elastic IPs: `plan()` only calls `describe_addresses`; `release_address` is called from `apply_region()` only and never in a dry run. Only addresses without `NetworkInterfaceId` that carry a `Tags` key are considered (BUG-020); there is no age gate (BUG-053), so the filter is the only protection: an empty `filter_tags` selects every tagged unassociated address. Exception tags skip an address (`policy.aws_eip_should_skip`); `notags` keeps an address when every notags key matches its tags, as for AWS VMs (`policy.notags_all`; BUG-011 fixed, `main` raised `TypeError`); a tag without `Key` or `Value` raises `KeyError` before any release when `notags` is set. Connectivity errors skip the region (SAF-001, `describe_regions` falls back to the static list, other errors propagate, SAF-004); every other error propagates and nothing is isolated per address (CLEANUP_SAFETY.md). Quirks in `docs/refactor/BUGS.md`: `BUG-051` to `BUG-054`.
- KMS: `plan()` calls `list_keys`, `list_resource_tags`, `describe_key` and `get_key_policy` only; `schedule_key_deletion` is called from `apply()` only and never in a dry run. Works in `us-west-2` only; a connectivity error there skips the cleanup (SAF-001) and every other list error propagates (SAF-004). Per key, any error skips that key (a bare `except:` on `main`, fail closed), and a skipped key is never selected: the policy statements are all read before the key is added (fixed BUG-055). Tags are read as `TagKey` / `TagValue` (a tag without them skips the key). `filter_tags`: every filter key must be on the key and its value must be any of the listed values; an empty value list means "key present, any value", as `policy.filter_tags_all_keys` (fixed BUG-007, BUG-014). `exception_tags` still read `Key` / `Value`, so with any exception tag set every tagged key raises `KeyError` and is skipped (BUG-015, left open: fixing it would delete tagged keys the production job keeps today, owner decision). The custom age tag is read with `core_age.get_retention_age` on the `TagKey` / `TagValue` tags (fixed BUG-008), so a tag shorter than `--age` selects a key earlier, as in every other cleaner (only reachable without `exception_tags`, since a tagged key is skipped before the age check otherwise); the age gate is `is_old` and a present but bad custom age tag keeps the key, counted as skip `bad_age_tag` (`get_retention_age` returns `KEEP_AGE`; SAF-006 to SAF-010, BUG-004 fixed). The same key can be scheduled twice (a policy with two statements naming `kms_user`) and a scheduling error aborts the run without a record of earlier keys (BUG-056, BUG-057). Quirks in `docs/refactor/BUGS.md`: `BUG-056` to `BUG-061`.
- VPC: the `--resource vpc` kind was removed (BUG-083, owner decision); `--resource vpc` is now an argparse invalid choice (exit 2). Rows BUG-012, BUG-083 to BUG-095, BUG-337 and BUG-367 are marked removed.
- Snapshots: `plan()` only calls `describe_snapshots` and `describe_images`; `delete_snapshot` is called from `apply()` (through `SnapshotCleaner.delete_one`) only and never in a dry run. The age gate is its own day cutoff, not `is_old`, so SAF-006 to SAF-013 do not apply as written: `policy.snapshot_old_enough`, a snapshot started exactly at `now - age_days` is old, `StartTime` after it is kept; a non-numeric or overflowing `age_days` raises `TypeError` / `OverflowError` before any call, while `0`, negative or `True` are accepted by `timedelta`. There is no `filter_tags`, `notags` or name filter, so every old snapshot of the account in every region is selected unless an exception tag (`policy.exception_tags_any`, one key at a time so the log names the first matching key; tag entries are read tolerantly: an entry without a key is ignored and a missing value reads as an empty string, BUG-144; tags that are not a list of mappings are read only after the age gate and raise for old snapshots) or an AMI of the same account and region protects it (`BUG-142` to `BUG-157` in `docs/refactor/BUGS.md`). Connectivity errors skip the region (SAF-001, `describe_regions` falls back to the static list, other errors propagate, SAF-004). Every other error while listing or deciding a region (client creation, `describe_snapshots`, `describe_images`, a malformed snapshot dict) is logged at ERROR, recorded in the run log (`fail(region, "-", error)` and `region_skipped`) and that region is skipped, the other regions continue, and a failing region deletes nothing (BUG-149); `describe_regions` errors and an invalid `age_days` raise (SAF-004). A `delete_snapshot` error of any kind is logged and swallowed and the snapshot is not recorded. Skip or listing-error log lines come before the `Deleted snapshot` lines. Quirks: `BUG-009`, `BUG-040`, `BUG-142` to `BUG-157`.
- VMs: see `crc/aws/vm/README.md`; `plan()` is read-only, `terminate_instances` and `stop_instances` run from `apply()` only and never in a dry run. Quirks: BUG-004, BUG-020, BUG-021, BUG-213 (fixed) to BUG-227 and BUG-351.
- Disks: `plan()` only lists volumes (describe_volumes paginator) and queries CloudWatch get_metric_data; `delete_volume` is called from `apply()` and `apply_region()` only and never in a dry run. An age gate is required (age and/or detach_age), CreateTime is compared with a floor that ignores MAX_AGE, and a missing CreateTime, invalid custom age tag or incomplete CloudWatch answer keeps the volume (SAF-006, SAF-010, SAF-014). Region errors never propagate (connectivity and unauthorised errors skip the region, others are logged and flagged); `describe_regions` errors other than connectivity propagate. Quirks: BUG-004, BUG-022 and BUG-282 to BUG-296; BUG-282 (all folded `yb_task` tags judged) and BUG-283 (CreateTime floor is effective age plus `detach_age` when both are set) are fixed.
- Spot instance requests: `plan()` only describes (a dry run is `plan()` alone and also performs the reads of the real path); tag, cancel, terminate, wait and delete happen in `apply()` in the order of CLEANUP_SAFETY.md (SAF-028 to SAF-033). Cancel before terminate; a failed tag or cancel aborts; leftover volumes are protected by their own exception, notags and sensitive yb_task tags; untagged requests and bad custom age tags are kept. Quirks: BUG-004, BUG-021, BUG-022 and BUG-272 to BUG-281.
- Region listing and connectivity: `get_all_regions` only calls `describe_regions` (read-only) and, on a connectivity error only (`CONNECTIVITY_ERRORS`, SAF-001), the static `get_available_regions`; every other error, including auth errors, propagates and is never replaced by a default region list (SAF-004), so a credential problem can not look like an unreachable region here. `CONNECTIVITY_ERRORS` must not grow to include `ClientError` or `NoCredentialsError`. Quirks: `BUG-302` to `BUG-307` in `docs/refactor/BUGS.md`.
- Logging (BUG-357, BUG-359, BUG-361, BUG-362): KMS `KEY SKIPPED`, snapshot `used by AMI` / `has tag`, keypair `not old enough` / `in exception_regex` lines are DEBUG; the cleaners report `REGION`, `ACTION` (`would_delete` / `deleted`), skip counts (`too_young`, `exception_tag`, `used_by_ami`, `not_ours`, `unreadable`, ...) and failures to `crc.core.logger.current()`.
- Do not call real cloud APIs in tests; mock every SDK client.

## Extension Rules

1. Behaviour changes need a `BUG-NNN` row in `docs/refactor/BUGS.md` and a test that fails without them.
2. New resources go in a new package with the `Cleaner` contract (`ARCHITECTURE.md`, "Add a cleaner"): a `Cleaner` registered with `@register("aws", ...)`, as every package here is.
3. Parity tests compare the cleaners with the frozen oracles in `tests/legacy/` (never edit the oracles); the key pair, Elastic IP, KMS, snapshot, disk and spot request tests drive the registered Cleaner through `crc.core.engine.run`: VM `tests/test_aws_vm_parity.py` (`tests/legacy/aws_vm.txt`) and `tests/test_aws_vm.py`; snapshot `tests/test_aws_snapshot_parity.py` (`tests/legacy/aws_snapshot.txt`) and `tests/test_aws_snapshot.py`; key pair `tests/test_aws_keypair_parity.py` (`tests/legacy/aws_keypairs.txt`); Elastic IP `tests/test_aws_ip_parity.py` (`tests/legacy/aws_elastic_ips.txt`); KMS `tests/test_aws_kms_parity.py` (`tests/legacy/aws_kms.txt`); disk `tests/test_aws_disk_parity.py` (`tests/legacy/aws_disk.txt`), `tests/test_aws_disk_cleaner.py` and `tests/test_aws_disk_engine.py`; spot requests `tests/test_aws_spot_instance_requests_parity.py` (`tests/legacy/aws_spot_instance_requests.txt`), `tests/test_aws_spot_instance_requests_cleaner.py` and `tests/test_aws_spot_instance_requests_engine.py`; `_base.py` `tests/test_aws_base_parity.py` and `tests/test_aws_base.py` (`tests/legacy/aws_base.txt`); `connectivity.py` `tests/test_aws_connectivity_parity.py` and `tests/test_aws_connectivity.py` (`tests/legacy/aws_connectivity.txt`).
4. Update this README and its symbol list with any public change.
5. Record every new bug or quirk in `docs/refactor/BUGS.md` (a new row cites the current `file:line` in `crc/`).
