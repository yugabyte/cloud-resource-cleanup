# crc.azu

## Purpose

Azure cleaners (azure-mgmt SDK). They delete or stop leftover VMs, disks, IPs and NICs in one resource group. Each kind is a registered `Cleaner` that the CLI runs through `crc.core.engine` (`crc/cli/routes/azu.py`): `plan()` reads the whole listing, `apply()` mutates. See `ARCHITECTURE.md` for the contract.

Modules:

- `_base.py`: `Base`: Azure credential from the `AZURE_CREDENTIALS_*` variables, and lazily built compute and network clients for a resource group. Its `os.environ` credential read is an ARCH-003 allowlist entry (`tests/archtest/bans.py`), so the credentials are read when an Azure cleaner is built.
- `_common.py`: `kept`, `log_would_delete`, `log_delete_summary`: log text and skip bookkeeping shared by ip, nic and disk
- `_logger.py`: thin Azure helpers over the current run of `crc.core.logger`
- `disk/`: subpackage (own README): `AzureDiskCleaner` (registered as `azure`/`disk`): deletes unattached managed disks (`begin_delete(...).result()`); any-key tag filter, age gate
- `ip/`: subpackage (own README): `AzureIpCleaner` (registered as `azure`/`ip`): deletes the unused IPs of the configured resource group (`begin_delete`); any-key tag filter
- `nic/`: subpackage (own README): `AzureNicCleaner` (registered as `azure`/`nic`): deletes NICs not in use (`begin_delete(...).result()`, three attempts); regex name filters
- `_created.py`: `AgeGate`, the creation-time lookup and age check of the ip and nic cleaners (`azure-mgmt-resource`).
- `spot_vm/`: `AzureSpotVmCleaner` (registered as `azure`/`spot_instances`): deletes stopped or deallocated Spot VMs and their leftover disks and NICs (subpackage with its own README)
- `vm/`: subpackage (own README): `VmCleaner` (registered as `azure`/`vm`): deletes (via `vm_delete_helpers`) or stops (`begin_deallocate`) VMs by power state
- `vm_delete_helpers.py`: `begin_delete_vm_and_wait`, `delete_vm_primary_nic`: delete helpers, no filtering

## Public API

The ip, nic, disk, vm and spot_vm subpackages document their own API in their own READMEs; the names below are synced with this README by ARCH-002. The package init holds only a copyright comment and declares no export list.

- `AgeGate`: the ip and nic age gate; reads creation times from the resource management client once per run and keeps a resource with none, or all of them when the lookup fails.
- `ResourceClient`, `ResourceOperations`: Protocols of the one resources listing call the gate uses; tests pass fakes.
- `real_run_age`: returns the age option, and raises a ValueError naming the age flag on a real run without a positive one.
- `Base`: Azure credential from the AZURE_CREDENTIALS_* environment variables (read when a cleaner is built) plus the lazily built, shared compute and network clients of one resource group; the client getters are typed as any object because each cleaner narrows the client with its own Protocol.
- `DeletePoller`: Protocol of the handle begin_delete returns (result(timeout)), used by the delete helpers.
- `begin_delete_vm_and_wait()`: starts a VM delete and waits on the poller (default timeout 3600 s), then logs the completion; errors propagate.
- `delete_vm_primary_nic()`: deletes the NIC named after the VM plus a suffix (default "-NIC") with up to 24 attempts 15 s apart; not-found counts as deleted and a final failure is logged, never raised.
- `kept()`: counts a kept resource under a skip reason and returns the not-selected decision (module _common, shared by the ip, nic and disk cleaners).
- `log_would_delete()`: one dry-run ACTION line per planned resource (module _common).
- `log_delete_summary()`: the closing warning lines logged for a resource kind (module _common); the NIC variant capitalises Number.
- `started()`, `region_done()`, `skip()`, `acted()`, `failed()`, `reason_slug()` (module _logger): thin Azure helpers over the current run of crc.core.logger. Azure has no regions, so `region_done()` logs one REGION line per resource group, with the resource group as region; `skip()` counts a skipped resource under a short snake_case reason (`reason_slug()`), `acted()` logs one ACTION line, `failed()` records a swallowed per-resource error. They only report, never decide.

## Safety Invariants

- Authoritative text: `CLEANUP_SAFETY.md`. Applicable IDs: SAF-006 to SAF-013 (age gates, shared by all clouds; SAF-011 met by disk, ip and nic), SAF-005, SAF-038, SAF-041, SAF-042, SAF-044.
- Known bugs and quirks: `docs/refactor/BUGS.md` rows `BUG-002`, `BUG-003`, `BUG-004`, `BUG-010`, `BUG-013`, `BUG-019`, `BUG-074` to `BUG-082`, `BUG-111` to `BUG-123`, `BUG-172` to `BUG-182`, `BUG-198` to `BUG-212`, `BUG-244` to `BUG-254`, `BUG-318` to `BUG-326`.
- Azure IPs: `plan()` only calls `list(resource_group)`; `begin_delete` is called from `apply()` only and never in a dry run. A real run (not `--dry_run`) needs a positive `--age` (BUG-075, SAF-011 met): without it `build_ip_cleaner` raises `ValueError` naming `--age` before any cloud call, while a dry run works without one. The creation time is not in the network SDK, so with an age the cleaner reads it from `azure-mgmt-resource` (`ResourceManagementClient(...).resources.list_by_resource_group(group, filter="resourceType eq 'Microsoft.Network/publicIPAddresses'", expand="createdTime")`, one call per run, ids matched case-insensitively); an IP with no creation time, a younger one, or every IP when the lookup fails is kept (`no creation time`, `not older than the age threshold`, `creation time lookup failed`). An empty `filter_tags` still selects every old unattached IP. An empty resource group raises `ValueError` before any SDK call. Only the configured resource group is listed, never the subscription, so a same-named IP elsewhere is never listed or acted on (BUG-074); an untagged IP (`tags` is `None`) has no tags and never raises, even when `exception_tags` or `notags` is set or `filter_tags` excludes it (BUG-013, BUG-077); an IP is kept with skip reason `in_use` when `ip_configuration`, `nat_gateway`, `linked_public_ip_address` or `service_public_ip_address` is set; the last three are read with `getattr` default `None`, while a model without `ip_configuration` still raises `AttributeError` before any delete (BUG-076). Nothing is isolated per IP: every error propagates and a later error leaves earlier IPs deleted. Quirks in `docs/refactor/BUGS.md` (`BUG-074` to `BUG-082`).
- Azure NICs: `plan()` only calls `network_interfaces.list(resource_group)` (twice; only the configured group is ever listed, `BUG-111`, `BUG-122`); `begin_delete(...).result()` is called from `apply()` only and never in a dry run. An empty `name_regex` (or one holding only empty strings) logs a warning and returns before any call. Selection is any NIC that is not in use (none of `virtual_machine`, `private_endpoint`, `private_link_service` set, skip reason `in_use`, `BUG-114`) whose name matches (`re.search`) a `name_regex` entry and no `exception_regex` entry (`BUG-113`). `exception_regex` also keeps a NIC whose name contains the entry literally. Patterns are compiled before any SDK call: an invalid pattern, a non-string entry, a bare string instead of a list, or an empty-string `exception_regex` entry raises `ValueError`; an empty-string `name_regex` entry is ignored. There is no tag filter. A real run needs a positive `--age` (BUG-112, SAF-011 met): `build_nic_cleaner` raises `ValueError` naming `--age` before any cloud call (a dry run works without one), and with an age the creation time comes from the same `azure-mgmt-resource` lookup as the IPs (`resourceType eq 'Microsoft.Network/networkInterfaces'`, `expand="createdTime"`, one call per run); a NIC with no creation time, a younger one, or every NIC when the lookup fails is kept. A failed delete is retried up to three times, logged and swallowed (the NIC is then missing from the result and the run still succeeds). Remaining quirks in `docs/refactor/BUGS.md` (`BUG-115` to `BUG-121`, `BUG-123`).
- Azure disks: `plan()` only calls `disks.list_by_resource_group(resource_group)` (BUG-172: only the configured group is listed, so a same-named disk elsewhere is never listed or acted on; the group is never derived from the listed disk's id); `disks.begin_delete(resource_group, name).result()` is called from `apply()` only and never in a dry run. Selection (an empty `filter_tags` selects every disk, so SAF-011 is not met by the tag filter): `filter_tags` any key (empty selects all, untagged disks match only when no filter), `exception_tags` any key, `notags` all keys, age through `core_age.get_retention_age` (a present but bad custom age tag returns `KEEP_AGE` and keeps the disk, BUG-004 fixed) and `core_age.is_old`, then the state test, which is a substring test (BUG-019). Each delete is isolated (BUG-174): the `begin_delete` poller is awaited before the disk counts as deleted, an error on one disk is logged (`Error occurred while deleting disk <name>: ...`), recorded in the run log (`_logger.failed`, `Result.failed`) and the loop goes on with the next disk; listing and selection errors (`time_created` or `disk_state` None, naive `time_created`) propagate. A real run needs a positive `--age` (BUG-173): `build_disk_cleaner` raises `ValueError` naming `--age` before any cloud call (a dry run works without one). Other quirks in `docs/refactor/BUGS.md` (`BUG-175` to `BUG-182`).
- Azure VMs: see `crc/azu/vm/README.md`. `plan()` only calls `list` (configured resource group) and `instance_view`; the VM and NIC deletes and `begin_deallocate` run from `apply()` only, never in a dry run. Untagged VMs are skipped (SAF-042), age goes through `crc.core.age`, per-VM errors are logged and swallowed (BUG-002, BUG-003, BUG-010, BUG-198). Other quirks in `docs/refactor/BUGS.md` (`BUG-199` to `BUG-212`).
- Azure Spot VMs: see `crc/azu/spot_vm/README.md`; `plan()` is read-only and re-raises when the list call fails (SAF-005), Spot VMs without tags are skipped (SAF-042).
- Azure plumbing: `Base` reads `AZURE_CREDENTIALS_SUBSCRIPTION_ID`, `AZURE_CREDENTIALS_TENANT_ID`, `AZURE_CREDENTIALS_CLIENT_ID` and `AZURE_CREDENTIALS_CLIENT_SECRET` (in that order) and `AZURE_RESOURCE_GROUP` (only when the resource group argument is falsy); it reads credentials from the environment only (a missing variable raises `KeyError` at construction, even in a dry run) and never logs the secret. `begin_delete_vm_and_wait` is called by the VM and Spot VM cleaners only when `dry_run` is `False`, and `delete_vm_primary_nic` checks `dry_run` before making any SDK call. The NIC helper never raises and records a not-found NIC as deleted (BUG-200, BUG-203, BUG-252, BUG-254, `BUG-318` to `BUG-326` in `docs/refactor/BUGS.md`). Tests: `tests/test_azure_base_parity.py`, `tests/test_azure_vm_delete_helpers_parity.py`.
- Logging (BUG-358, BUG-361, BUG-362): every cleaner (vm, spot_vm, disk, ip, nic, `vm_delete_helpers`) reports to `crc.core.logger.current()`: one REGION line per resource group, one ACTION line per resource deleted, stopped or listed in a dry run, skip counts under short reasons, and swallowed per-resource errors (VM processing, Spot VM, leftover Spot disk, NIC after three attempts, VM primary NIC after 24 attempts) through `failed()`. The raw tag dumps of disks and VMs and the per-leftover-disk skip lines are DEBUG. Unattached (no `begin()`), these calls log nothing.
- Engine path (BUG-392): the CLI runs `ip`, `nic`, `disk`, `vm` and `spot_instances` through `crc.core.engine`; `plan()` reads the whole listing before `apply()` mutates, so a listing or selection error stops the pair before any delete. A real `AzureIpCleaner` run logs its `REGION` line from `apply()` after the deletes (a dry run from `plan()`), so a failed delete leaves the line out.
- Do not call real cloud APIs in tests; mock every SDK client.

## Extension Rules

1. New resources go in a new module with the `Cleaner` contract (`ARCHITECTURE.md`, "Add a cleaner"): a `Cleaner` registered with `@register("azure", ...)`.
2. A new module follows `ip/`, `nic/`, `disk/`, `vm/` and `spot_vm/`: a Cleaner with an injected client Protocol, `@register("azure", ...)`, a test against a frozen oracle in `tests/legacy/`. Update this README and its symbol list with any public change.
3. Keep `Base`, the delete helpers and their call order, environment variables, log lines and swallowed errors as they are; a cleaner narrows the `Any` clients with its own Protocol instead of changing the plumbing's return types.
4. Record every new bug or quirk in `docs/refactor/BUGS.md` (a new row cites the current `file:line` in `crc/`).
