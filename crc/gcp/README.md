# crc.gcp

## Purpose

GCP cleaners (google-cloud-compute). They delete or stop leftover instances, disks and addresses. Each kind is a `Cleaner` registered with `@register("gcp", ...)` and run through `crc.core.engine` by the route table `crc/cli/routes/gcp.py`. Any change must follow `ARCHITECTURE.md`, with `make check` green.

Modules:

- `_base.py`: `get_gcp_regions`
- `_scan.py`: `ZoneScan` and `log_action`, the run-log helpers shared by the four cleaners
- `_common.py`: `is_old_enough`, the age gate (timestamp, custom age label, `core_age.is_old`) shared by the disk and VM cleaners, and the `TIME_FORMAT` and `Clock` they share
- `disk.py`: re-exports the disk names; `disk_cleaner.py` holds `DiskCleaner` (registered as `gcp` / `disk`) and `disk_settings.py` `DiskSettings` and the result helpers. Deletes unattached disks by `last_detach_timestamp` (zonal disks of every zone); label any-key filter; `notags` (as the VM cleaner) and `name_regex` (`re.search`) are applied; `age` is not used
- `disk_client.py`: `DiskView`, `GcpDiskClient` and `ComputeDiskClient`, re-exported by `disk.py`
- `ip.py`: re-exports the IP names; `ip_cleaner.py` holds `IpCleaner` (registered as `gcp` / `ip`) and `ip_client.py` the client protocols and `ComputeIpClient`. Deletes RESERVED addresses (`AddressesClient().delete`, waits for the operation) by `creationTimestamp` (`age`), substring name and exception filters
- `spot_vm/`: subpackage with its own README; the import path is `crc.gcp.spot_vm`
- `vm_client.py`: `GcpVmClient`, `InstanceView` and `ComputeVmClient`, re-exported by `vm.py`
- `vm.py`: re-exports the VM names; `vm_cleaner.py` holds `VmCleaner` (registered as `gcp` / `vm`), and `vm_settings.py` `VmSettings`. Deletes (`delete`) or stops (`stop`) RUNNING instances by labels (all keys), `notags` and exception labels, and age

## Public API

The names below are synced with this README by ARCH-002. The spot_vm subpackage documents its own API in its own README. The package init holds only a copyright comment and declares no __all__.

- `get_gcp_regions()`: returns the region names of a project (one Compute Engine regions client list call), a plain list in listing order. It builds a new client per call, has no fallback and lets every SDK error propagate.

- `is_old_enough`: the shared age gate of the disk and VM cleaners: parses the timestamp, reads the custom age label (fail closed: a present but bad label keeps the item, BUG-004 fixed), logs an "Updating age" line when it is set and returns whether the item is old enough for the effective age; pure apart from logging.
- `ZoneScan`: counts the resources listed and selected in one zone or region and logs the REGION line through the current run log when finished; log text only (BUG-361).
- `log_action`: logs the ACTION line (would_delete, deleted, would_stop or stopped) of one candidate through the current run log.
- `AddressView`: Protocol of the three address fields read (name, status, creation_timestamp); tests pass fakes.
- `OperationView`: Protocol of the long-running delete operation the delete call returns; waiting for it (result) raises when it failed (BUG-064).
- `GcpIpClient`: Protocol of the three Compute Engine calls used (list_regions, list_addresses, delete_address); tests pass fakes.
- `ComputeIpClient`: the google-cloud-compute implementation of `GcpIpClient`; it builds a new RegionsClient or AddressesClient for every call.
- `IpCleaner`: the Cleaner (supports, read-only plan, mutating apply, plus regions, plan_region and apply_region); its failures attribute lists the failed deletes since the last apply (BUG-063).
- `build_ip_cleaner()`: registry factory behind @register("gcp", "ip"); reads project_id, name_regex, exception_regex and age from RunContext.options; raises ValueError without a project_id and, unless the run is a dry run, without a positive age (BUG-062).
- `DiskView`: Protocol of the four disk fields read (users, name, labels, last_detach_timestamp); tests pass fakes.
- `GcpDiskClient`: Protocol of the Compute Engine calls used (list_zones, list_disks, delete_disk, get_operation, close); tests pass fakes.
- `ComputeDiskClient`: the google-api-python-client (zones, deletes) plus google-cloud-compute (disk listing) implementation of `GcpDiskClient`; it builds the discovery service lazily, once per run, builds the disks client right after the zones were listed, and close() closes the service.
- `DiskSettings`: frozen dataclass with the fields the cleaner reads (project_id, filter_labels, exception_labels, exception_regex, custom_age_tag_key, detach_age, slack_notify_users, slack_user_label, notags, name_regex, wait_sec, poll_sec).
- `DiskCleaner`: the Cleaner (supports, read-only plan, mutating apply, partial_succeeded for the report-then-reraise bridge mode, plus zones, plan_zone and apply_disk); plan_zone is a lazy generator, consumed in full by plan() before apply() deletes.
- `build_disk_cleaner()`: registry factory behind @register("gcp", "disk"); reads project_id (ValueError without it), filter_tags, exception_tags, exception_regex, notags, name_regex (ValueError for a non-list or an invalid pattern), custom_age_tag_key, detach_age (a positive value is required unless the run is a dry run, BUG-124), slack_notify_users and slack_user_label from RunContext.options.
- `InstanceView`: Protocol of the four instance fields read (status, name, labels, creation_timestamp); tests pass fakes.
- `GcpVmClient`: Protocol of the Compute Engine calls used (list_zones, list_instances, delete_instance, stop_instance, get_zone_operation for BUG-185); tests pass fakes.
- `ComputeVmClient`: the google-api-python-client (zones, deletes, stops) plus google-cloud-compute (instance listing) implementation of `GcpVmClient`; it builds the discovery service in list_zones, builds the instances client right after the zones were listed and closes the service at that point, and later deletes and stops still use the closed service object.
- `VmSettings`: frozen dataclass with the fields the cleaner reads (project_id, filter_labels, exception_labels, notags, age, custom_age_tag_key, instance_state, wait_sec and poll_sec for the zone operation wait).
- `VmCleaner`: the Cleaner (supports DELETE and STOP, read-only plan, mutating apply, plus zones, plan_zone and apply_instance); plan_zone is a lazy generator.
- `build_vm_cleaner()`: registry factory behind @register("gcp", "vm"); reads project_id (ValueError without it), filter_tags, exception_tags, notags, age (a positive value is required unless the run is a dry run, BUG-183), custom_age_tag_key and instance_state from RunContext.options; the operation (delete or stop) is the RunContext operation.

## Safety Invariants

- Authoritative text: `CLEANUP_SAFETY.md`. Applicable IDs: SAF-006 to SAF-013 (age gates, shared by all clouds), SAF-021 to SAF-024, SAF-037, SAF-039, SAF-041, SAF-043, SAF-044, SAF-045.
- Known bugs and quirks (`docs/refactor/BUGS.md`; fix one only in its own change that names the `BUG-NNN`): rows `BUG-004`, `BUG-005`, fixed, `BUG-006`, fixed, `BUG-023`, `BUG-062` (fixed), `BUG-065` to `BUG-073`, `BUG-124` to `BUG-141` (`BUG-124`, `BUG-126` and `BUG-127` fixed), `BUG-183` to `BUG-197` (`BUG-183` fixed), `BUG-228` to `BUG-243`, `BUG-297` to `BUG-301`.
- The GCP disk cleaner (`DiskCleaner`) uses `--detach_age`, never `--age` (SAF-021, SAF-022); Spot VMs skip GKE and instance group members (SAF-045).
- GCP IP: `plan()` only calls `RegionsClient().list` and `AddressesClient().list`; `AddressesClient().delete` is called from `apply_region()` only and never in a dry run. There is no tag filter. Age gate (BUG-062 fixed): a real run requires a positive `--age`; the registered factory raises `ValueError` naming `age` before the client is built (a dry run needs none and then lists every RESERVED address). Each address that passes the name filter must be at least `age` old by its `creationTimestamp` (`TIME_FORMAT` parsing as the disk and VM cleaners, `core_age.is_old`, `MAX_AGE` still applies); a younger address is kept (skip `too_young`) and one whose timestamp is missing or unreadable is kept and recorded as a run-log failure. The route passes `options.age` only when the flag was given. An empty `filter_regex` still selects every RESERVED address (`policy.filter_substring_matches`) that is old enough. `exception_regex` excludes every address whose name contains any entry (BUG-001 fixed; it was inverted; `--exception_regex` is not passed by the Jenkins jobs). `delete()` waits for the returned long-running operation (`.result()`) before an address is logged and recorded as deleted (BUG-064 fixed). A failed delete (Google API/auth/OS error, including a failed or timed-out operation) is logged at ERROR, recorded in the run log (`fail`), skipped and the loop goes on, so the addresses already deleted stay recorded and the summary is logged (BUG-063 fixed); any other exception is recorded and re-raised. Region and address listing errors still propagate unchanged (there is no connectivity fallback). No SAF ID is specific to this module. The Cleaner lists every region first, then deletes region by region, so a listing error stops the run before any delete. Quirks are in `docs/refactor/BUGS.md` (`BUG-062`, `BUG-065` to `BUG-073`).
- GCP disk: `plan()` only calls `service.zones().list().execute()` and `DisksClient().list`; `service.disks().delete().execute()` is called from `apply_disk()` only and never in a dry run (ARCH-005). A disk is deleted only when it is unattached (`users` empty), has a `last_detach_timestamp`, is not excluded by `exception_regex` (`policy.exception_regex_match_matches`, `re.match`) or `exception_labels` (`policy.exception_tags_any`), matches `filter_labels` (`policy.filter_tags_any_key`; empty matches all, an unlabelled disk fails an active filter) and is at least as old as the custom age label or else `detach_age` (`policy.effective_age`, `core_age.is_old`, `MAX_AGE` still applies). The age gate is `--detach_age` only (SAF-021, SAF-022): `age` is never read, so `--age` cannot protect a disk; `notags` (skip when every key matches, as the VM cleaner; BUG-005) and `name_regex` (`re.search` any pattern, empty matches all; an invalid pattern or a non-list raises `ValueError` before any call; BUG-006) are applied; a real run requires a positive `detach_age` (BUG-124 fixed): the registered factory raises `ValueError` naming `detach_age` before the client is built, for an omitted, empty, zero or `None` value, and `--age` is no substitute; a dry run without `detach_age` still lists every unattached disk with a detach timestamp; a present but bad custom age label keeps the disk (`get_retention_age` returns `KEEP_AGE`, counted as skip `bad_age_tag`; BUG-004 fixed). The clock comes from `RunContext.now`, never read inside the cleaner. After each delete the zone operation is polled until DONE without error (the GCP spot helper `wait_operation`, 180 s, every 5 s); a missing operation name, an operation error, a poll error or a timeout is logged, recorded as a run-log failure and the disk is not recorded as deleted (BUG-126). A failed delete or wait is logged (`Error occurred while deleting disk ...`), recorded as a run-log failure and skipped. An error while evaluating one disk (timestamp parse, regex, `MAX_AGE`, missing field) keeps that disk, is logged (`Error occurred while evaluating disk ...`) and recorded, and the loop continues; a listing error of one zone (including while iterating) is logged and recorded as `zone <name>` and the zone skipped (BUG-127). The zones listing and the disks client still raise (no connectivity fallback). The Cleaner lists and filters every zone first, then deletes disk by disk, so an error while listing a later zone stops before any delete. Quirks are in `docs/refactor/BUGS.md` (`BUG-124` to `BUG-141`).
- GCP VM: `plan()` only calls `service.zones().list().execute()` and `InstancesClient().list`; `service.instances().delete()` and `.stop()` (`.execute()`) are called from `apply_instance()` only and never in a dry run (ARCH-005). An instance is acted on only when its status is in `instance_state` (default `RUNNING`, `policy.state_in`), it is not excluded by `exception_labels` (any key) or `notags` (all keys) (`policy.should_skip_by_tags`), carries every `filter_labels` key (`policy.filter_tags_all_keys`; empty matches all, an unlabelled instance fails an active filter) and is at least as old as the custom age label or else `age` (`policy.effective_age`, `core_age.is_old`, `MAX_AGE` still applies). A real run, delete or stop, requires a positive `--age` (BUG-183 fixed): the registered factory raises `ValueError` naming `age` before the client is built, also when a custom age label is configured (the label replaces `age` per instance, never the requirement); a dry run needs none. A present but bad custom age label keeps the instance (`get_retention_age` returns `KEEP_AGE`, counted as skip `bad_age_tag`; BUG-004 fixed). The clock comes from `RunContext.now`, never read inside the cleaner. After `delete` or `stop` the cleaner waits for the zone operation (`zoneOperations().get()`, polled every 5 s for at most 180 s, as the Spot cleaner does) and records the instance only when the operation is `DONE` without an `error` (BUG-185, fixed); a failed call, a response without an operation name, an operation error, a poll error or a timeout is logged (`Error occurred while delete instance ...`), recorded with `fail()` and the instance is not recorded. An error while evaluating one instance (timestamp parse, `MAX_AGE` parse, missing `labels` or `status`) is logged (`Error occurred while evaluating instance ...`), recorded with `fail()` and the instance is kept; an instance listing error for a zone, also mid-iteration, is logged (`Zone ... failed listing GCP instances`), recorded with `fail()` and `region_skipped()`, and the zone is skipped with no `REGION` line; the run goes on with the next instance or zone (BUG-186, fixed). The project-level zone listing (`zones().list()`) still raises (fail closed: nothing was acted on, and an auth or connectivity error must fail the run), as does a zone entry without a `name`. The Cleaner lists and filters every zone first, then acts, so an error raised by the zone listing stops before any delete. Quirks are in `docs/refactor/BUGS.md` (`BUG-183` to `BUG-197`; `BUG-183`, `BUG-185` and `BUG-186` are fixed).
- GCP plumbing: `get_gcp_regions()` is read-only (only `RegionsClient().list`); it reads no environment variable, config or credential source itself (the SDK default credentials apply), logs and prints nothing, has no connectivity fallback and swallows no error (BUG-067: a listing or auth error, also mid-iteration, propagates and the partial list is lost). Region names are not filtered, deduplicated or validated, and `project_id` is passed to the SDK unchecked. Quirks are in `docs/refactor/BUGS.md` (`BUG-297` to `BUG-301`).
- Do not call real cloud APIs in tests; mock every SDK client.

### spot_vm

`crc/gcp/spot_vm/` is a subpackage with its own README (public names, safety invariants). `SpotVMCleaner` is registered as `gcp` / `spot_instances` (`build_spot_cleaner`); It deletes Spot or preemptible VMs (RUNNING, TERMINATED, SUSPENDED) that match `filter_labels` (all keys) and the age gate, skips GKE nodes and managed instance group members, then deletes `autoDelete=false` disks after the instance operation completes (SAF-039, SAF-044, SAF-045). Any change needs `tests/test_gcp_spot_instances_parity.py` (oracle `tests/legacy/gcp_spot_vm.txt`, never edit it) to stay green. Quirks are in `docs/refactor/BUGS.md` (`BUG-228` to `BUG-243`).

- Logging (`docs/logging.md`; BUG-358, BUG-361, BUG-362): The label dump of every listed disk and instance (`logging.info(labels)`), the address dump of the IP cleaner and the per-disk `Skipping leftover Spot disk ...` line are DEBUG. Every zone or region pass logs one `REGION` line when its listing is exhausted (`ZoneScan`); every delete or stop (or, in a dry run, every would-be one) logs one `ACTION` line, in `apply_*()` and, for a dry-run `plan()`, in `plan()`; skipped resources are counted with `logger.current().skip(reason)` (`state`, `exception_tag`, `exception_regex`, `filter_mismatch`, `attached`, `never_detached`, `too_young`, `not_spot`, `managed_or_gke`, `disk_exception_tag`); a swallowed per-resource error is also recorded with `fail()` (the IP cleaner records and re-raises). A Spot zone whose listing fails calls `region_skipped()` and logs no `REGION` line.

## Extension Rules

1. New resources go in a new module with the `Cleaner` contract (`ARCHITECTURE.md`, "Add a cleaner"): a `Cleaner` registered with `@register("gcp", ...)`.
2. Update this README and its symbol list with any public change (ARCH-002).
3. GCP IP changes need `tests/test_gcp_ip_parity.py` (oracle `tests/legacy/gcp_ip.txt`, never edit it) to stay green.
4. GCP disk changes need `tests/test_gcp_disk_parity.py` (oracle `tests/legacy/gcp_disk.txt`, never edit it) to stay green.
5. GCP VM changes need `tests/test_gcp_vm_parity.py` (oracle `tests/legacy/gcp_vm.txt`, never edit it) to stay green.
6. Record every new bug or quirk in `docs/refactor/BUGS.md`.
7. GCP plumbing changes need `tests/test_gcp_base_parity.py` (oracle `tests/legacy/gcp_base.txt`, never edit it) to stay green. `__init__.py` stays a copyright comment with no export list.
